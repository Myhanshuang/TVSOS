## 第 1 份｜后端·统计计算引擎与指标落地

**一句话**：把集体定下的每个指标变成每 3 秒能推送真数的后端实现。

### 工作内容

- **统计主链路**：`stats.go CalculateGlobalStats()`（957 行，10 个子模块）→ `realtime_stats.go BuildRealtimeDashboard()`（587 行）→ WS `/ws/stats` 推送
- **指标支撑表**：metric_snapshot / matching_log / track_log / emission_factor 建模与迁移（38bd7f6）
- **匹配质量 M1-M4**（`matching_quality.go`）：条件最优参考答案（固定其余指派、该单改派各车取整批成本最低者），逐单候选排名 + ground truth 回填 matching_log；精确率 / 召回率（未派单计未命中）/ F1 / MRR（58bc9c5）
- **C1 基线对比**：同批贪心首可行基线 vs SA 成本改善%；**R1-R3 可靠性**（`reliability_stats.go` MTBF/MTTR/可用性）；**T1 匹配吞吐**；**A2 求解计时**（`solver_timing.go`）；**A3 精确枚举 gap**（`gap_evaluator.go`）（af9a22f / 58bc9c5）
- **沙箱化适配**：指标全部改 experiment_id 作用域 + 虚拟时钟观测窗口

### 汇报讲点

- 全局枚举 20 辆车组合爆炸 → 条件枚举 O(单数×车数) 的规模无关参考答案，及其与全局最优的强弱关系
- 为什么召回率分母要含未派单运单（否则 P=R=F1 退化失去区分度）
- 滚动指标值与落库明细分离：线上算趋势，DB 留可回放证据

### 演示建议
跑一个实验，开地图覆盖层指给观众：M / C / R 卡片的数值各自来自哪张表。

### 工作量依据
提交 38bd7f6、b6e1a2d（后端字段）、af9a22f（含前端卡片同步）、58bc9c5，核心 Go 约 2000 行。

## 第 2 份｜后端·司机与随机事件引擎

**一句话**：给仿真装上「会拒单、会累、会遇上车祸」的真实司机，为指标提供事件侧数据源。

### 工作内容

- **司机对象建模**：driver 表、等级、连续驾驶时长、与车辆绑定（8e5ddb9）
- **四类事件全状态机**：拒单（概率 + 同单上限防死循环）/ 疲劳休息（阈值触发）/ 极端天气（暂停移动）/ 车祸（进维修 + system_event fault + 恢复状态机：在途续跑→待发车→释放空闲）
- **pause_until 暂停机制**：地图上车辆冻结、速度归零的底层支撑
- **random_event 表**：R4-R6 / F2 / 前端事件流的口径基础
- **沙箱化适配**：现场摇号改为预生成脚本到点消费（与第 5 份衔接，计在 f1e851a）

### 汇报讲点

- 拒单与派单质量的交互建模：事件不是噪声，而是指标的一部分
- 车祸→维修→自动恢复的三态恢复逻辑，为什么恢复比触发难写
- level_factor 等级修正：高等级司机更稳的概率修正

### 演示建议
把事故概率临时调高跑实验，在地图上指认「维修中 / 等待中(天气)」车辆与其恢复过程。

### 工作量依据
提交 8e5ddb9（f1e851a 的脚本化事件消费部分亦归本份），Go 约 650 行——状态机复杂度高于行数，故兼最轻一份，建议兼任开场综述。
**交接句**：「后端的数都齐了——下一份讲这些数在运行期怎么展示给用户。」

**一句话**：把集体设计的领域模型落成真实的表、隔离的查询和一道登录门。

## 第 5 份｜后端·沙箱引擎与全套 API

**一句话**：让「同一种子 → 逐 tick 完全一致」成立——沙箱科学性的根基。

### 工作内容

- **ExperimentRuntime**（`experiment_runtime.go` 609 行）：单实验串行生命周期、单线程 masterLoop 固定顺序（释放订单 → SA 派单 → 消费事件脚本 → 恢复 → 移动 → 快照）（f1e851a P3）
- **虚拟时钟**（`virtual_clock.go`）：虚拟时间 = 起点 + tick×步长，倍速只改真实 tick 频率
- **全随机源种子化**：rt.rng 单一 RNG，SA / 司机 / 拒单全走它
- **确定性数据生成器**（`sandbox/gen`，0f22d20 P4）：摇号序固定（司机等级 → 订单流泊松 → 天气 / 车祸逐 tick，车祸带 level_factor），输出订单流 + 事件脚本入 experiment_order / experiment_event；v2 等级移入生成阶段（8eae75b）；4 项单测
- **全套 API**（0f22d20 P5）：沙箱 / 方案 / 实验 CRUD、生命周期、种子导出导入（DataGeneratorVersion 版本校验）、compare
- **复现验证**：同种子双实验总成本逐位一致（35025.80213604554 两次一致）

### 汇报讲点

- 输入确定（预生成脚本）+ 决策确定（种子）双保险，缺一不可
- 虚拟时钟把仿真时间与墙钟解耦，指标口径 / 倍速 / 快照因此自洽
- 为什么单线程 tick：并发乱序是复现性天敌

### 演示建议
同种子建两个实验，结果页对比总成本逐位一致（A2 墙钟耗时除外，顺带解释为何除外）。

### 工作量依据
提交 f1e851a（P3）+ 0f22d20 + 8eae75b，Go 约 1600 行含单测。
**交接句**：「引擎能跑出可复现的实验了——最后一份讲研究者怎么把它用起来。」

## 第 6 份｜前端·沙箱页面流与结果工具链

**一句话**：把沙箱能力包装成「登录 → 建沙箱 → 配参数 → 跑实验 → 对比 → 导报告」的完整工作流。

### 工作内容

- **沙箱页面流**：sandboxList（默认主页）/ sandboxDetail（方案 + 实验记录 + 导入导出）/ experimentConfig（图形化表单与 TOML 双向同步、scheme-mode 方案存档）、header 场景切换 + 虚拟时钟进度（6cb9d13）
- **页面流健壮性**：catch-all 兜底路由、确定性 goSandboxPage、退出实验轮询时序、三请求各自兜错重试（e65bfec / 1fcc4f6 / a6086d4）
- **终态结果页可视化**（`experimentResult.vue` 628 行）：T/U/C/A/M/R/G + 事件积压 8 组卡片、率值比例条、P50/P95/P99 分位条、事件 timeline、车队构成 / 货类需求条形图（7c5618d）
- **参数 diff 可视化**：自实现 LCS 行级 diff → 统一 diff → 分栏对照视图（左基准 / 右对比，红删绿增）（6555e52 / 22483a5）
- **报告导出三格式**：HTML 自包含（可打印 PDF）/ Markdown 同构 / JSON 全量；SA 收敛序列等值压缩 2520 → 13 个变化点（974d5d2）

### 汇报讲点

- 种子 = 论文的实验记录：参数 TOML + 种子 + 生成器版本三要素
- 参数 diff 是参数敏感性分析的入口
- 导出三格式对应三种受众：HTML 给人看、Markdown 进文档、JSON 进分析脚本

### 演示建议
现场完整走一遍（5 分钟）：新建实验改参数 → 导出种子 → 导入复建 → 跑完 → 对比看 diff → 导出 HTML 报告。

### 工作量依据
提交 8 个（6cb9d13 / e65bfec / 1fcc4f6 / a6086d4 / 7c5618d / 6555e52 / 22483a5 / 974d5d2），前端约 1900 行。
**收尾句**：「从指标定义、计算、展示，到可复现实验与对比报告，实现闭环完成。」
