## 0. 现状结论（侦察摘要）

### 后端（tvsos-backend/）
- 仿真引擎是**进程级全局单例**：main.go 启动 5 个无停止机制的死循环 goroutine（CreateOrderTask / SimulateMoving / BroadcastStatsLoop / MetricSnapshotLoop / RandomEventLoop），全部包级函数+全局变量，无可实例化结构。
- 随机性**完全不可复现**：SA 调度器每批 `rand.Seed(time.Now().UnixNano())`（sa_scheduler.go:35）；天气/车祸/拒单/时长区间全用全局 `math/rand`（random_event.go 5 处）；MockShipments 种子也是当前时间。
- 13 张表全部无沙箱/实验维度；repository 层 10 个文件直接操作全局 `database.DB`。
- Redis 仅 runtime_route_store.go 使用，key 无实验维度（`mover:route:*`）。
- **登录为零**：无 user 表、无 auth handler、无中间件、无 JWT 依赖。前端 login.vue 是纯前端假登录（不调 API）。
- 无"开始/暂停/停止实验"概念，仿真随进程启动即运行。
- `internal/task/*_test.go` 直连真实 MySQL 并 DELETE 清库（红线，必须在本次一并解决）。
- go.mod 已有 pelletier/go-toml/v2（indirect），解析 TOML 零新依赖。

### 前端（tvsos-frontend/）
- 路由 4 条，无守卫；`/admin/home` = index.vue（横向 scroll-snap 三屏：地图/统计/任务）。
- mock 订单入口仅 header.vue 一处（L30/34-46/149-155）。
- 统计面板 statistics2.vue：WS 优先 + 15s 轮询兜底，8 章指标全部组件内私有状态。
- user store 有 token 字段但无调用方；request.js 拦截器 token 逻辑形同虚设。

## 1. 总体架构设计

### 1.1 核心概念模型

```
User（研究人员/实验者）
  └── Sandbox（沙箱 = 世界设定：基础设施 + 世界规则）
        └── Experiment（实验 = 一次运行：参数 TOML + 种子 + 结果数据）
              └── Run 数据（订单流、任务、事件、指标快照、轨迹……全部带 experiment_id）
```

- **Sandbox（沙箱级，固定）**：路网/POI 子集、车辆类型库与车队定义、仓库、费率表、订单生成模型参数、随机事件概率模型、作业时间分布、仿真时间尺度、算法版本。存 `sandbox` 表（TOML 全文 + 关键索引列）。
- **Experiment（实验级，每次可变）**：种子 random_seed、车辆数量/配比、订单负载、算法超参（SA 温度/冷却率/迭代数、候选 K）、成本权重（优化目标指标选择 C2/U2/U4/T2 权重）、约束条件（司机工时上限等）、仿真时长。存 `experiment` 表（TOML 全文 + 状态机 + 研究者外键 + 种子）。
- **数据生成器**：实验创建后、启动前，由生成器按"沙箱世界规则 + 实验参数 + 种子"**确定性预生成**本实验的订单流（含虚拟时间戳）与随机事件脚本（车祸/天气/拒单/疲劳的时间点与对象），落库为本实验专属输入。仿真运行期不再现场摇号，而是消费预生成数据 → 这是可复现性的根基。

### 1.2 执行模型（待评审 Q1，默认按方案 A 写）

**方案 A（推荐）：单实验串行执行**。同一时刻全系统只有一个"活跃实验"。新增 `ExperimentRuntime`（引擎实例对象，见 §4），启动实验时绑定该实验的数据作用域与种子 RNG，停止/完成后解绑。UI 流程天然契合（开始实验 → 地图页 → 完成 → 退出）。
**方案 B：多实验并行**。需要 repository 全层加维度、WS 频道隔离、车辆 ID 冲突处理，工作量约 3 倍，不建议本期做。

### 1.3 可复现性等级（待评审 Q2，默认按等级 2 写）

- **等级 1（统计复现）**：同种子 → 同订单流、同事件脚本、同 SA 序列；但 tick 走真实时钟，疲劳累计/暂停时长/批次分组受时序影响，结果只能近似一致。
- **等级 2（严格复现，推荐）**：实验运行时引入**虚拟仿真时钟**——所有推进（车辆移动、事件触发、统计采样）按固定步长的虚拟 tick 进行；前端倍速只改变"虚拟时间流逝速率"；种子 + 预生成数据 + 确定性 tick ⇒ 同种子结果逐 tick 一致。工作量集中在 vehicle.go / random_event.go / stats 采样的时钟源替换。

### 1.4 数据隔离（待评审 Q3，默认按方案 A 写）

**方案 A（推荐）：同库 + 维度列**。
- 新增元数据表：`user`、`sandbox`、`experiment`、`experiment_result`（终态指标汇总，对比视图直接读它）。
- 运行数据 8 表加 `experiment_id`（+索引）：vehicle/driver/shipment/order_task/random_event/matching_log/metric_snapshot/track_log。
- **注意**：vehicle/driver 在沙箱视角是"基础设施"，在运行期是"状态"。处理：实验启动时从沙箱车队模板**实例化复制**一批本实验专属的 vehicle/driver 行（experiment_id 标记），运行只动这些行；沙箱模板行永不运行。这样不同实验互不影响，也天然支持"不同实验车辆数不同"。
- `poi` / `cargo` / `emission_factor` / `handling_config` 作为全局只读基础数据共享（POI 是地理事实，不需要按沙箱复制；若沙箱要用不同 POI 子集，在 sandbox TOML 里记录 poi_ids 白名单）。
- Redis key 加实验维度：`{prefix}:exp:{experiment_id}:route:*`，实验结束清理。
- **`internal/task` 的危险测试改为强制读取 `config-test.yml` 指向的独立测试库**，没有该文件直接 Skip——解除清库红线。

方案 B（每沙箱独立 schema）：隔离更强但 GORM 动态切库、迁移管理复杂，不推荐。

## 4. 引擎沙箱化重构（核心）

### 4.1 ExperimentRuntime 实例对象

```go
type ExperimentRuntime struct {
    ExpID      uint
    Sandbox    *model.Sandbox
    Params     *ExperimentParams      // TOML 解析产物
    RNG        *rand.Rand             // 实验专属种子 RNG（SA 用）
    Clock      VirtualClock           // 等级 2：虚拟时钟；等级 1：真实时钟封装
    Speed      float64                // 每实验倍速（替换全局 atomic）
    WorldRules *WorldRules
    cancel     context.CancelFunc
}
```

- main.go 不再启动 5 个全局死循环；改为 `runtimeManager`（单例，但只持有一个活跃 runtime，方案 A）。
- 原 5 个循环改为 runtime 的方法：`go rt.dispatchLoop() / rt.moveLoop() / rt.statsLoop() / rt.snapshotLoop() / rt.eventLoop()`，由 rt.cancel 停止。
- repository 调用点全部传入 expID 过滤（或引入轻量 `repository.Scope(expID)` 包装）。
- realtime.Hub 增加按实验广播（方案 A 下可直接全局广播，因为只有一个活跃实验；代码上预留 expID 字段）。
- simulation_speed 全局 atomic 移到 runtime 上；/simulation/speed 接口作用于当前活跃实验。

### 4.2 随机源种子化清单（全部改为 rt.RNG 或生成器 RNG）
| 位置 | 现状 | 改法 |
|---|---|---|
| sa_scheduler.go:35,43,63,89-100 | 全局 rand+时间种子 | `assignBySimulatedAnnealing(..., rng *rand.Rand)` |
| random_event.go:123,173,302,312,393 | 全局 rand | 运行期不再摇号 → 消费预生成事件脚本；残留处传 rng |
| shipment_handler.go:119 MockShipments | 时间种子 | **删除**（被数据生成器取代） |
| scripts/gen_mock_data.go | 时间种子+清库 | 重写为数据生成器（见 §5） |

### 4.3 生命周期 API
```
POST /experiments/:id/start    -- 校验状态 ready → 实例化车队/司机 → 建 runtime → 状态 running
POST /experiments/:id/stop     -- 停止 runtime，落 experiment_result，状态 finished/aborted
GET  /experiments/:id/status   -- 运行状态/虚拟时钟/进度
```

### 4.4 时钟（等级 2）
- `VirtualClock`：虚拟时间 = 起点 + tick 数 × step（step 可配，默认 10s 虚拟/tick）；推进速率 = 真实间隔 × speed。
- pause_until、疲劳累计、事件触发、metric_snapshot.snapshot_time、order_task 各阶段时间戳全部改用虚拟时钟。
- 这是严格复现的关键改动，也是 R/T 系指标口径变化点（需在指标文档中注明）。

## 5. 数据生成器

形态（待评审 Q8，默认 API 触发）：
- `internal/sandbox/gen/` 新包：`Generate(sandbox, params, seed) → (orders []GenOrder, events []GenEvent)`。
- 输入：沙箱世界规则（订单到达分布/日均单量/波动、装卸时间分布、事件概率）+ 实验参数（车辆数、订单量、仿真时长）+ 种子。
- 输出落库：`experiment_order`（experiment_id, virtual_time, start_poi, end_poi, cargo_id, count）与 `experiment_event`（experiment_id, virtual_time, type, target, params）两张预生成表；或复用 shipment/random_event 表以 `status='scripted'` 区分。
- 确定性保证：生成器内部 `rand.New(rand.NewSource(seed))`，纯函数无 IO 依赖；同 seed 同参数 → 逐字节一致（加单元测试断言）。
- 生成器版本号 `data_version` 记入 experiment，种子导入时校验兼容。
- 拒单/疲劳这类"依赖运行态"的事件：按概率模型预生成"候选事件"，运行时到点检查条件是否仍满足，不满足则跳过——这一点会导致等级 1 下的轻微分叉，等级 2 下完全确定。

## 6. 实验参数 TOML Schema（草案）

```toml
# ============ 实验级参数（每次实验可调的"旋钮"）============
seed = 12345                       # 随机种子（种子导入=整文件导入）

[simulation]
duration_hours = 24                # 虚拟仿真时长（结束条件，见 Q6）
tick_seconds = 10
speed = 1.0

[fleet]                            # 运力规模（覆盖沙箱模板）
vehicle_count = 20
type_mix = { heavy = 8, medium = 8, mini = 4 }

[orders]
daily_volume = 200                 # 订单负载
arrival_model = "poisson"          # 分布模型（覆盖世界规则时可配）
peak_hours = [9, 10, 17, 18]

[algorithm]                        # 算法超参
mode = "hybrid"
sa_initial_temp = 1000.0
sa_cooling_rate = 0.95
sa_min_temp = 0.1
sa_iters_per_temp = 50
candidate_k = 5

[objectives]                       # 全局优化目标指标权重（需求 1）
weights = { C2 = 1.0, U2 = 0.5, U4 = 0.3, T2 = 0.3 }
soft_constraints = { F1_gini_max = 0.4, G2_carbon_max = 99999 }

[random_events]                    # 随机事件概率（覆盖世界规则）
driver_refuse_prob = 0.06
weather_prob_per_tick = 0.0005
accident_prob_per_tick = 0.0002
rest_after_hours = 4
rest_minutes = 20

[constraints]                      # 约束条件
driver_max_hours = 8
vehicle_max_mileage_km = 800
```

沙箱级 TOML（基础设施+世界规则）结构类似，含路网/POI 白名单、车辆类型库、费率表、分布模型、时间尺度、算法版本。

## 10. 风险与注意

1. **虚拟时钟改动面大**（等级 2）：pause_until 目前存真实 datetime 并与 time.Now() 比较，改虚拟时间涉及字段语义变化——需要数据迁移或新增 virtual_pause_ticks 列。
2. **R1-R3 可靠性指标**口径依赖"最近一次 startup 事件"，实验化后改为按实验窗口，需要同步修改 reliability_stats.go 与指标文档。
3. **高德地图 key** 硬编码在 mapContainer.vue（L126-130），本次顺手迁 env。
4. 实验运行中后端重启 = 实验中断：方案 A 下约定"重启即 abort 当前实验"（记录状态），不做运行态恢复（原 RecoverRuntimeState 逻辑在沙箱化后按实验维度重估）。
5. task 包测试清库红线必须在 P1 解决，否则数据生成器联调期间随时可能毁掉种子数据。

### 12.2 PDF《数据实验沙箱》对齐要点

PDF 的核心框架：**沙箱 = 环境模拟器 + 数据记录器 + 分析器**，存储分四层。映射到本系统：

| PDF 分层 | 内容 | 本系统落地 |
|---|---|---|
| 实验配置层 | 实验ID/描述/创建时间/研究人员/参数范围（PDF p15 示例） | `experiment` 表 + params TOML + created_by |
| 环境数据层 | 地理(POI坐标/类型/道路/限速) 交通(拥堵/天气/事故) 时间(开始时间/加速比/时间窗) 经济(油价/过路费/工资)（PDF p5-10） | `sandbox` 表 world_rules TOML 按 **geography / traffic / time / economy** 四段组织（见 §12.3）；POI 全局共享 |
| 算法数据层 | 算法类型/超参/random_seed/运行状态（PDF p17） | `experiment` 表 params TOML [algorithm] 段 + seed + data_version |
| 结果数据层 | run_id/总成本/总里程/准时率/计算时间/利用率/约束违反（PDF p18-19） | `experiment_result` 表（primary_metrics JSON 对齐这些字段） |

PDF 带来三个计划增量：
1. **算法性能指标**纳入结果记录：单批求解耗时已有（A2），补充内存占用与 SA 收敛曲线（每温度最优 cost 序列）存入 experiment_result。
2. **经济环境参数**显式入沙箱 world_rules：[economy] 段（油价/过路费/司机时薪/装卸费），cost.go 的 Cost A-F 改为从当前实验的沙箱规则读取而非硬编码/全局配置。
3. **交通环境模型**：PDF 要求拥堵/时段交通条件可控。世界规则加 [traffic] 段（分时段速度系数），车辆推进时速 = 基准速度 × 时段系数。初版用确定性分时段系数表（随虚拟时钟变化，不破坏严格复现），复杂拥堵模型留扩展。

### 12.4 "方案/批次"层级映射（PDF p20 界面草图）

PDF 界面是"方案 → 批次1/2/3"三级；需求是"沙箱 → 实验"。折中方案（**待确认 Q9**）：
- `experiment_scheme`（实验方案）= 沙箱内一份命名参数模板（TOML），可编辑/复制。
- `experiment`（实验/批次）= 由某方案发起的一次运行，含**参数快照 + 种子 + 状态 + 结果**。种子不同即不同实验，满足需求 8。
- "再次运行"（PDF p20）= 用方案参数新建一个实验（可改种子）。
- 数据只挂在 experiment 一层，不引入第三层数据载体，复杂度可控。

### 12.5 登录简化设计（按 Q4 结论）
- `user(id, username, password_hash, display_name, created_at)`，bcrypt 哈希。
- POST /auth/login 返回简单 token（UUID，服务端内存/Redis 记录，进程重启即失效，无刷新无角色）。
- 中间件仅校验 token 存在性；实验 created_by 记录登录用户。
- 迁移时插入种子账号（如 admin/admin123）。
- 明确不做：角色权限、找回密码真实邮件流、token 刷新、多端登录管理。
