## 1. 项目与现状概览

### 1.1 架构

- **后端**：Go（Gin + GORM + MySQL）。包含 SA（模拟退火）调度引擎、NF（Next Fit）兜底、实时 WebSocket 推送、`routing` 高德路径规划子服务、`routing-python-tool` 工具。
- **前端**：Vue3 + Element Plus + ECharts + 高德地图。包含地图大屏、实时看板 `statistics2.vue`、算法演示页。

### 1.2 核心数据模型

| 实体 | 关键字段 | 状态/阶段 |
|---|---|---|
| `vehicle` 车辆 | license, lon/lat, speed, tybe(6 类), size, reserved_size, capacity, empty_mileage, distance, duration, wait_time, total_wait_time, angle | Free / Ready / Running |
| `shipment` 订单 | startPoiId, endPoiId, createTime, updateTime, cargoId, count | Sleeping / Queued / Waiting / Working / Finish |
| `order_task` 任务 | shipmentId, vehicleId, createTime, updateTime | Planned / Accepting / Transporting / Finish |
| `cargo` 货物 | name, tybe, pack, weight | — |
| `poi` 装卸点 | name, tybe, lon, lat, status | — |

### 1.3 核心业务流程

后台守护轮询 `GetSleepingShipment()`（每 5s，每批 5 单）→ SA（或 NF 兜底）按 `CalculateCost`（综合代价 F）分配车辆 → 创建 `order_task` → 车辆模拟移动（每 10s，受仿真倍速控制）按 Accepting/Transporting 阶段累计空驶/重载里程 → 到达终点完成 → 拉取下一单。`CalculateGlobalStats()` 构建全局快照 `Statistics`，`BuildRealtimeDashboard()` 推送 WebSocket 快照与 24 点趋势。

### 2.4 成本模型（Cost A–F）要点

| 项 | 含义 | 组成 |
|---|---|---|
| A | 直接成本 | 车辆等待总量 + 空驶里程 |
| B | 快运成本 | 加权货物等待 + 最慢货物等待 |
| C | 效率+公平 | 空驶占比 + 等运占比 + 最长车辆等待 |
| D | 平台成本 | 剩余总运能 + 最小剩余运能 gap |
| E | 风险成本 | (A+B+C+D)/4 + 三类时间标准差加权 |
| F | 综合成本 | A–E 加权求和 + 方向角惩罚；`TotalCost = F` |

### 2.5 已有指标体系的优点

1. **模块化程度高**：`Statistics` 按车辆/利用率/时间/距离/货物/吞吐/损耗/装卸划分，互不干扰，易扩展。
2. **基础统计能力完整**：集中/离散趋势由 `computeBasicMetrics` 统一提供（max/min/avg/median/stddev）。
3. **估算透明机制**：`LoadStats.Estimated` 显式标注估算值，具备基本的数据真实性管理意识。
4. **成本闭环耦合**：Cost F 直接驱动 SA 调度选车，指标具备业务可驱动性。
5. **实时链路成熟**：快照 + WebSocket + 简易趋势已打通。

### 2.6 已有指标体系的不足（对照参考文档的差距）

| # | 缺口 | 现状 | 对应类别 |

| 2 | 里程/装载口径不全 | 里程利用率缺真实轨迹版；装载率无标准差与体积口径 | 2 资源利用效率 |

## 3. 新科学指标体系设计

### 3.1 设计原则

1. **九维全覆盖**：完整对齐参考文档 9 大类别，每类至少 1 个可计算、有公式、有数据源的核心指标。
2. **现状兼容**：保留全部现有指标（标记"保留"），按新框架归类；不足项标记"改造"，缺失项标记"新增"。
3. **可落地分级**：每个指标标注 **数据来源、计算位置、优先级**（P0 现有数据即可算 / P1 需轻量打点或补字段 / P2 需新表新模块或实验）。
4. **估算透明**：凡基于直线距离/经验系数估算的指标沿用并强化 `Estimated` 标注，并给出精确化路径。
5. **口径统一**：统一"成本用吨·公里、等待用秒、效率用百分比"度量规范；趋势类指标全部时序化（由内存 24 点扩展为历史落库）。

### 3.2 总体框架：9 维度 × 三级层级

- **L1 战略/总览**（看板顶层）：综合调度成本(F)、运力利用率（吨公里）、综合运输效率、单位成本、单位吨公里碳排放、服务可用性 —— 面向决策者。
- **L2 战术/过程**（调度调优）：匹配精准度、利用率明细、响应时间分位、算法复杂度、周期稳定性、公平性 —— 面向调度策略。
- **L3 明细/诊断**（问题定位）：等待/空驶/装卸/吞吐/损耗/拒绝等明细统计 —— 面向开发与运营排查。

### 3.3 指标字典（核心设计）

#### 维度 1 · 匹配算法精准度（车找货）

| ID | 指标 | 公式/定义 | 数据来源 | 现状 | 优先级 |
|---|---|---|---|---|---|
| M1 | 精确率 Precision | TP/(TP+FP)，系统认为正确的匹配中真正正确的比例 | 匹配决策日志 + 专家/精确解标注集 | 新增（需评估数据集） | P2 |
| M2 | 召回率 Recall | TP/(TP+FN)，真正最优匹配中被找回的比例 | 同上 | 新增 | P2 |
| M3 | F1-Score | 2·P·R/(P+R) | 由 M1/M2 推导 | 新增 | P2 |
| M4 | 平均倒数排名 MRR | Σ(1/正确车辆在推荐列表中的排名)/N | SA/NF 候选排名输出（现有 `collectNFCandidates` 可复用） | 新增 | P2 |

> **说明**：本系统为"货找车"（SA 将 shipment 分配给 vehicle），参考文档"车找货"场景在本系统中对偶为"推荐/分配决策评估"——为每单构建多候选排名（现有候选集逻辑已具备），以"成本最优车辆/专家标注"为 ground truth。

#### 维度 2 · 资源利用效率

| ID | 指标 | 公式/定义 | 数据来源 | 现状 | 优先级 |
|---|---|---|---|---|---|
| U1 | 车辆里程利用率 | 载重里程/总里程 ×100%；与空驶率互补 | `TotalLoaded/(TotalEmpty+TotalLoaded)`（估算版）；真实版需轨迹表 | 改造 | P1 |
| U2 | 重量装载率 | 实际装载/额定载容，报告**均值 + 标准差**（负载均衡度） | `UsedCapacity/TotalCapacity`（均值已有）；标准差由 `CurrentLoadStats` 分布计算 | 改造（补标准差） | P0 |
| U3 | 运力利用率（吨公里） | 已用运力吨公里/可用运力吨公里 | 分子 `TotalTonDistance` 已有；分母需定义 = Σ(Capacity×仿真时长×平均速度) 或理论满载吨公里 | 改造 | P1 |
| U4 | 空驶率 | 空驶里程/总里程 = EmptyFullRatio/(1+EmptyFullRatio) | 现有 `EmptyFullRatio` | 保留+推导 | P0 |

#### 维度 3 · 系统吞吐量与响应时间

| ID | 指标 | 公式/定义 | 数据来源 | 现状 | 优先级 |
|---|---|---|---|---|---|
| T1 | 匹配吞吐量 | 单位时间成功匹配事务数（matches/hour） | 调度入口打点（`assignShipmentToVehicle` 成功计数 + 时间戳） | 新增（轻量计数） | P1 |
| T2 | 匹配响应时间分布 | 货物生成(`shipment.CreateTime`)→完成匹配(`order_task.CreateTime`)，报告 **P50/P95/P99** | 现有时间戳即可算；扩展 `computeBasicMetrics` 支持分位数 | 改造（扩分位统计） | P0 |
| T3 | 吞吐量-响应时间曲线 | 负载递增实验（`MockShipments` N 从 100→10000），找吞吐峰值与响应拐点 | 实验脚本 + 打点 | 新增 | P2 |

#### 维度 4 · 算法与调度效率

| ID | 指标 | 公式/定义 | 数据来源 | 现状 | 优先级 |

| A1 | 时间复杂度 | 理论（SA 主循环 ≈ O(iters×N×LIFO-DFS)）+ 实测时间-规模曲线 | 基准测试脚本 + 运行计时 | 新增 | P1 |

| 无匹配决策日志 | 新增 `matching_log`（shipment→候选排名→选中） | M1–M4 | P2 |
| 无运行事件记录 | 新增 `system_event` 表（故障/恢复/重启） | R1–R3 | P1 |
| 无排放因子/装卸系数配置 | 配置表化（车型排放因子、装卸秒/吨系数） | G1–G2、装卸时间标定 | P1 |

### 3.6 行业分层先进评估体系（进阶扩展，超越 P/R/F1/MRR）

**定位**：P/R/F1/MRR 仅覆盖"排序推荐层"。本项目是 **运筹优化 × 在线动态决策 × 排序推荐** 三层问题的交叉，业界（网约车/货运平台派单、EMS 车辆调度、VRP/调度研究）采用**按问题层面分层**的评估体系。本节为"进阶全集"，与 3.3 的"必备最小集"互补；全部指标均与算法实现解耦，可随算法演进平移。

#### 层面 A · 优化解质量评估（运筹标准，本项目最该补）

| 指标 | 含义 | 本项目落点 |
|---|---|---|
| **Optimality Gap** | (启发式解 − 最优解)/最优解 | 小规模用枚举/ILP 求精确解；大规模用下界（LP 松弛/分块下界） |
| **可行解率** | 满足硬约束（容量/车型/时间窗）的解占比 | SA 的 feasible 判定已有，统计可行比例 |
| **解稳定性/方差** | 多随机种子多次运行的解均值与标准差 | 比单次最优更真实，评估算法稳定性 |
| **收敛质量/时间到目标 (TTT)** | 到达 95% 最优所需迭代数 | 已有收敛曲线动画，转成定量指标 |
| **鲁棒性/扰动敏感度** | 订单量、POI 分布扰动下解的退化程度 | 仿真系统可做敏感性实验 |

#### 层面 B · 在线/动态决策评估（业界派单系统主流）

| 指标 | 含义 |
|---|---|
| **竞争比 Competitive Ratio** | 在线算法解 / 离线（先知）最优解——评估"订单即时到达必须当下派单"的核心指标 |
| **遗憾值 Regret** | 每步决策与最优决策的累计差距 |
| **离线回放 (Offline Replay) + A/B** | 用同一条订单流分别跑不同策略（SA vs NF vs 随机），对比累计成本/空驶/等待——Convoy、Uber 派单评估的标准范式 |

> 对本项目：**离线回放最易落地**——已有 `MockShipments` 生成订单流、`scheduler.mode` 可切换 nf/hybrid、仿真可重复，天然具备"同输入不同策略对照实验"条件。

#### 层面 C · 排序/推荐质量进阶（MRR 之上的精细版）

| 指标 | 相对 MRR 的优势 |
|---|---|
| **NDCG@k / Recall@k / Precision@k** | MRR 只看第一个正确项；NDCG 评估整个候选排名质量，更贴近"给司机展示前 k 个可接单"场景 |
| **MAP** | 多相关项场景（一辆车可接多个单） |
| **覆盖率 Coverage** | 有多少车辆被匹配系统利用，避免"少数车抢单、多数车饿死" |

#### 层面 D · 公平性（比单一基尼更全面）

- **Gini / 洛伦兹曲线**（已有）
- **Jain's Fairness Index**：资源分配领域标准，直接衡量"每车工作量"均衡度
- **Envy-free（无嫉妒）**：每车都不觉得"换给别人更差"（稳定性/核心解角度）
- **Max-min / 最差车保障**：关注最弱势车辆，防止系统性边缘化

#### 层面 E · 多目标/帕累托评估（Cost A/B/C/D/E 本质是五目标加权）

- **帕累托前沿**：成本 vs 效率 vs 公平的权衡曲线
- **超体积指标 Hypervolume**：一组解在多目标空间的支配覆盖面积
- **加权鲁棒性**：权重扰动下最优解是否跳变

#### 层面 F · 端到端业务 KPI（货运平台日常使用）

**First Pass Yield（首次匹配成功率）**、**On-time Pickup/Delivery**、**Empty Miles**、**Dwell Time（装卸停留）**、**Cost per Load**——大多在当前 snapshot 中已有雏形，按时间窗/按天聚合即可。

#### 针对本项目的推荐组合与优先级

1. **P0：Optimality Gap + 解稳定性**（层面 A）——小规模精确枚举已有雏形（`findMinLIFORouteDistance` 的 DFS 穷举），可直接扩成"SA 解 vs 最优解 gap"，是答辩最能体现科学性的点。
2. **P0/P1：离线回放 + 基线对照**（层面 B）——复用 `MockShipments` + `scheduler.mode`，跑"同订单流下 SA vs NF vs 随机"的累计 Cost/空驶/等待对比，补上参考文档 C1 的"基线对比"，业界范式成熟。
3. **P1：NDCG@k / Recall@k**（层面 C）——现有 `collectNFCandidates` + Cost 排序输出即可算。
4. **P1：Jain's Fairness Index + 最差车保障**（层面 D）——现有 vehicle 聚合数据可算。
5. **P2：竞争比 Competitive Ratio**（层面 B 理论版）——需离线重放订单流 + 离线最优解，学术上最有分量。

### 3.7 算法演进适配性（局部最优 → 全局最优）

**结论**：**能胜任**。本体系是**黑盒/结果层评估**——绝大多数指标度量"调度结果在车队上留下的痕迹"（空驶/装载/等待/成本/公平/碳排放），与算法内部如何搜解无关。只要算法优化同一个 Cost 目标、受同样的物理约束（容量/车型兼容/LIFO），**指标定义与公式全部不变**，无论 SA、贪心、匈牙利算法、ILP/MILP 还是 CP-SAT。

#### 逐类影响矩阵

| 维度 | 指标 | 受算法切换影响？ | 切换后的角色 |
|---|---|---|---|
| 2 资源利用 U1–U4 | 里程/装载/运力利用率 | 否，纯结果指标 | 不变 |
| 3 吞吐响应 T1–T3 | 吞吐、响应分位、曲线 | 否（但权重上升） | **更关键**：精确算法更慢，成为"能否上线"的门禁 |
| 5 周期稳定 S1–S3 | Jitter/合规率/峰值延迟 | 否，订单生成与算法无关 | 不变 |
| 6 成本效益 C1–C3 | 成本变化/单位成本/ROI | 否，Cost 模型独立于算法 | 不变 |
| 7 可靠性 R1–R3 | MTBF/MTTR/可用性 | 否 | 不变 |
| 8 公平满意 F1–F3 | 基尼/Jain/拒绝率 | 否 | **更重要**：算法切换后用于回归对比公平性 |
| 9 绿色 G1–G2 | 碳排放 | 否 | 不变 |
| 4 算法效率 A1–A3 | 复杂度/gap | **是，角色转变** | gap 从"启发式 vs 最优"泛化为"解 vs 界/正确性验证" |
| 1 匹配精准 M1–M4 | P/R/F1/MRR | **部分退化** | 若 ground truth=最优解，P/R/F1 饱和为 1.0；MRR/NDCG 仍有效 |

#### 三个关键点

1. **A3 优化 Gap 不失效，反成核心量化武器**
   - 启发式（SA）下：gap 度量"SA 解离全局最优差多少"，是"要不要换全局最优算法"的**决策依据**。
   - 精确求解器下：gap 角色转为**正确性验证**（小规模用暴力枚举验证求解器确实找到全局最优），或改用 **MIP gap（|原始解 − 对偶界|/|对偶界|）**——即 Gurobi/CP-SAT 自带的解质量口径。
   - 定义只需泛化为"解 vs 参考基准（最优解或对偶下界）"，公式框架不变，且恰好能量化"SA 局部最优 vs 全局最优差距"。

2. **M1–M4（P/R/F1）可能饱和**
   若 ground truth 直接取精确最优分配，P/R/F1 恒为 1.0 失去区分度，退化为**回归/冒烟检查**；真正有区分度的是推荐层 MRR/NDCG@k 与 B 层竞争比/回放对比。

3. **T1/T3 从"参考"变"门禁"**
   完整 PDP+LIFO 是 NP-hard，ILP 求解时间随 N 指数上升，而调度循环是**每 5s 一批、每批 5 单**。T1（匹配吞吐）、T2（P99 响应）、T3（吞吐-响应曲线）会立刻暴露"精确解太慢、订单堆积"，成为判断"全局最优能否放进实时回路"的硬性验收指标。业界标准做法是**双层架构：离线/周期全局最优重算 + 在线轻量调度**，本体系可同时评估两层。

#### 为平稳承接算法切换，建议补两项基础设施

1. **同输入回放回归基线（最重要）**：把离线回放 A/B 从 P1 升为基础设施。算法改动后用**同一条订单流**分别跑旧/新算法，逐项 diff 所有结果层指标（Cost/空驶/等待/公平/碳排放）。
2. **精确求解器质量接口**：在调度层加"解质量报告"入口（primal/dual bound、MIP gap、求解时间），让 A3 在精确算法下无缝续命。

## 6. 风险与假设

- **假设 1**：参考文档"车找货"场景在本系统对偶为"货找车"的分配/推荐决策评估；MRR 依赖现有候选集逻辑扩展排名输出。
- **假设 2**：无真实轨迹前，U1/G1 等里程类指标采用直线距离估算值并显式标注；轨迹精确化为 P2。
- **假设 3**：Cost F 保留为综合调度成本口径；C1 基线采用现有 `scheduler.mode` 的 NF/随机对照，不新增算法。
- **假设 4**：可靠性（R1–R3）基于新增运行事件表，历史故障无法回溯（未记录过），从上线起算。
- **假设 5**：调度算法可能演进为全局最优（ILP/CP-SAT 等），本体系按"黑盒/结果层"设计，指标与算法解耦；切换后 A3 泛化为 MIP gap、M1–M4 降级为 sanity check。
- **风险 1**：M1–M4/A3 需要 ground truth（最优解/专家标注），工作量与主观性较大，故定 P2。
- **风险 2**：P1 涉及的建表/打点改动需同步前端看板与 Swagger 文档，变更面较大，需按分支流程推进。
- **风险 3**：若全局最优求解时间超出每 5s 批次窗口，T1/T3 将触发实时性告警，需采用"离线/周期全局最优 + 在线轻量调度"双层架构。

## 7. 结论

现有指标体系已具备良好的统计地基（14 个子模块快照 + Cost A–F 闭环 + 实时看板），但对照 `plans/科学指标设计.md` 的 9 大类别，**匹配精准度、系统吞吐与响应分位、算法复杂度与 gap、周期稳定性、成本效益、可靠性、公平性、绿色低碳** 八个类别基本空白。本报告在保留全部现有指标的基础上，补齐上述类别，形成 **"9 维度 × L1/L2/L3 三层级"** 的完整指标体系，并按 **P0/P1/P2** 给出可执行的落地路径：P0 用现有数据立即补齐分位数/标准差/单位成本/优化 gap；P1 通过轻量打点、阶段时间戳、历史采样落库与配置表化补齐吞吐、成本效益、可靠性、公平性、绿色指标；P2 建设匹配精准度评估、吞吐-响应实验与真实轨迹日志，实现指标的最终科学化闭环。

在此基础上，3.6 节进一步引入**行业分层先进评估体系**（优化解质量 → 在线动态决策 → 排序推荐 → 公平性 → 多目标 → 业务 KPI），将参考文档的 P/R/F1/MRR 定位为"排序推荐层"的入门指标，并给出针对本项目的升级组合（Optimality Gap、离线回放 A/B、NDCG@k、Jain's Fairness Index、竞争比）。3.7 节论证了本体系对**算法演进（局部最优 → 全局最优）**的适配性：指标体系与算法实现解耦，切换后 A3 泛化为 MIP gap、M1–M4 降级为 sanity check、T1/T3 成为实时性门禁，并以"同输入回放回归基线 + 精确求解器质量接口"两项基础设施保障算法切换的平稳承接。
