## 一、项目背景与平台总览

### 1.1 平台定位

TVSOS 是一个**模拟成都地区货运调度**的仿真实验平台：以"沙箱实验"为核心范式，支持研究者定义世界规则 → 配置实验参数 → 生成确定性数据 → 运行仿真 → 产出指标结果 → 跨实验对比，形成完整的"调度算法实验闭环"。

### 1.2 技术栈与架构

| 层 | 技术 | 说明 |
|---|---|---|
| 后端 | Go (Gin + GORM + MySQL) | 单实验串行运行时、虚拟时钟、种子 RNG |
| 前端 | Vue3 + Element Plus + ECharts + 高德地图 | 地图可视化、凹字形数据覆盖层、结果/对比页 |
| 仿真引擎 | 预生成脚本 + 单线程 tick | 订单流/天气/车祸预生成落库，逐 tick 顺序消费 |
| 数据层 | 9 张运行表按 experiment_id 隔离 | 沙箱模板与实验实例分离 |

### 1.3 平台核心流程

```
User(研究者) → Sandbox(世界设定) → ExperimentScheme(参数模板) → Experiment(批次)
    → 生成数据(种子确定性) → 开始实验 → 地图/任务管理/实时看板
    → 到达固定虚拟时长自动完成 → 结果页(全量指标+导出) → 对比页(跨实验横向对比)
```

### 1.4 严格复现性设计（平台科学性基石）

- **虚拟时钟**：所有时间语义（派单/事件/快照）均为虚拟时间，与真实时钟解耦；
- **种子 RNG**：调度算法、司机等级、拒单判定全部走实验种子随机源；
- **单线程 tick**：主循环固定执行序（释放订单 → 求解派单 → 消费事件 → 恢复 → 移动 → 快照）；
- 同种子 + 同参数 ⇒ **逐 tick 一致**（已验证：总成本两次运行完全一致）。

## 二、科学指标体系（优化的对象基础）

平台落地了 M/U/T/A/C/R/F/G 八章共 40+ 项实时指标（口径见 `docs/统计指标总结与全局优化对象.md`，本报告仅列与优化直接相关的核心项）：

| 维度 | 指标 | 口径 | 在优化中的角色 |
|---|---|---|---|
| 成本 | C2 单位成本 | 总成本 F / 总吨公里 | 主目标候选（裁决性） |
| 利用 | U2 装载率均值 | 单车 size/capacity 均值 | 主目标候选 |
| 利用 | U4 空驶率 | 空驶里程 / 总里程 | 主目标候选 |
| 响应 | T2 匹配响应 P95 | 分配时刻 − 创建时刻 | 主目标候选（尾部时效） |
| 公平 | F1 基尼系数 | 装载率洛伦兹曲线 | 软约束（≤0.4） |
| 绿色 | G2 吨公里碳排 | 排放因子 × 里程 / 吨公里 | 软约束 |
| 算法 | M1-M4 / C1 / A3 | 条件最优参考/贪心基线/精确枚举 gap | 算法层质量评估 |

**关键权衡关系**（多目标优化的动因）：

1. U2（装载率）↔ T2（响应）：拼车凑载 → 订单积压 → 响应劣化——帕累托前沿的两端；
2. U4（空驶率）↔ T2（响应）：原地等单降空驶 → 响应变慢；见单即派则空驶上升；
3. C2 是 U2/U4 的合成，但只压空驶不考虑等待，C2 不一定下降。

> 单目标标量化（旧 Cost F 唯一口径）会**隐性牺牲**部分维度——多目标化是必然选择。

## 三、多目标优化：主要目标法 + 帕累托考量

### 3.1 问题建模

采用 **"1 主目标（四选一）+ 其余指标软约束"** 框架（ε-约束法）：

- **主目标**：C2↓ / U2↑ / U4↓ / T2 P95↓ 四选一，实验参数 `[objectives].primary` 配置，**支持随时选择与更换**；
- **软约束**（软性限制，非硬排除）：其余三个主目标 + F1 基尼 + G2 碳排；
  - **绝对预算**：`budgets = { U4_max = 0.45, ... }`，用户显式设定；
  - **自适应 ε 预算**：锚定当前全局值 × (1±容差)，即"**不劣化超过容差**"语义（实验初期指标无有效值时自然失活）。

```toml
[objectives]
mode      = "primary"       # primary(主要目标法) / weighted(旧口径兼容)
primary   = "C2"            # C2 / U2 / U4 / T2
tolerance = 0.15            # 非主目标劣化容差（自适应 ε 预算）
budgets   = { F1_gini_max = 0.4 }
```

### 3.2 求解机制（五层设计）

1. **批次投影口径**：SA 在一个派单批次内可优化的增量指标，与全局同名指标同源可比：

   | 指标 | 批次投影 |
   |---|---|
   | C2 | 批次综合成本 / 批次吨公里 |
   | U2 | 指派后全车队装载率均值 |
   | U4 | LIFO 路线空驶占比 |
   | T2 | 批次响应投影 P95（现有等待 + 接驾时间） |
   | F1/G2 | 指派后装载分布基尼 / 吨公里碳排投影 |

2. **ε-约束标量化**（主目标法核心）：

   ```
   score = 主目标归一项（初始解标定尺度，量纲无关）
         + 8.0 × Σ 软约束相对违反量（相对预算的超限比例）
         + 硬约束惩罚（超载/绕路一票否决，与旧口径同量级）
   ```

3. **帕累托支配接受准则**：候选解在 4 主目标上支配当前解 → 无条件接受（沿前沿自由移动）；否则按 ε 分数走经典 Metropolis（温度控制探索）。

4. **有界帕累托档案**：全程维护 ≤32 个非支配解（去重、剔除被支配成员、容量淘汰），保留探索中发现的权衡解。

5. **ε-终选**：批次终解在档案中按标量化分数裁决——惩罚系数保证"**可满足软约束**"近似字典序优先于"**主目标最优**"，即主要目标法的最终语义。

### 3.3 算法层口径联动（科学性细节）

M1-M4（条件最优参考答案）、C1（贪心基线对比）、A3（精确枚举 gap）与调度器**共用同一目标上下文**——主目标切换后，"最优车"的定义随之切换，算法层指标度量的始终是**当前目标下的求解质量**，避免"换了目标还用旧参考答案"的口径错位。

### 3.4 结果与展示层

- 收敛曲线：`bestPrimary`（主目标原始值）/`bestViolation`/`paretoSize` 逐温度采样；
- `primary_metrics`：`objective_mode` / `primary_objective` / `primary_objective_value` / `objective_feasible_pct`（软约束可满足批次占比）/ `pareto_avg_front` / `pareto_last_front`；
- 前端：实验配置表单（主要目标单选 + 容差 + 绝对预算折叠区）；结果页主目标卡片高亮 + 帕累托前沿表格；对比页多目标对比行；地图覆盖层实时显示优化口径。

## 四、求解算法插件化体系（可更换的优化算法）

### 4.1 插件架构

所有求解算法实现统一的 **`Solver` 接口**并注册进 `solverRegistry`；派单入口 `solveDispatch` 按 `[algorithm].solver` 选择插件：

```go
type Solver interface {
    Name() string        // 代号（与 [algorithm].solver 匹配）
    DisplayName() string
    Solve(sc *SolveContext) SolveOutput
}
```

**派发器统一职责**（算法无关）：共享初始解生成 → 主目标尺度标定 → 插件求解 → 帕累托档案合并候选集 → **ε-终选** → 多目标运行统计 → 结果映射。**插件只负责"搜索"本身**——新增算法零改动调度链路。

### 4.2 七个可选求解器

| 代号 | 算法 | 核心机制 | 独有超参（TOML） |
|---|---|---|---|
| `sa` | 模拟退火 | 温度调度 + Metropolis；接受准则叠加帕累托支配判定 + 有界档案 | sa_initial_temp / sa_cooling_rate / ... |
| `nsga2` | NSGA-II | 快速非支配排序 + 拥挤度截断（μ+λ 环境选择）；二元锦标赛 + 均匀交叉 | population / generations / crossover_prob / mutation_prob |
| `nsga3` | NSGA-III | Das-Dennis 参考点（H=4 → 35 点）+ 极值点 ASF 归一化 + 小生境计数保留 | + ref_divisions |
| `moead` | MOEA/D | 权重向量分解为标量子问题 + 邻域内解替换；聚合前按当代极值归一 | + neighborhood / decomposition（tchebycheff/weighted_sum/pbi） |
| `spea2` | SPEA2 | 强度 S → 原始适应度 R + k-近邻密度 D；档案迭代截断保多样性 | + archive_size |
| `mopso` | MOPSO | 粒子 = 指派编码；速度更新 w·v + c1·(pbest) + c2·(gbest)，softmax 采样离散化；外档案随机 leader | + inertia_weight / cognitive_coef / social_coef |
| `nf` | 贪心首可行 | 顺序取第一辆可行车（C1 基线同口径，无迭代无随机） | candidate_k |

配置示例（实验可选任意算法，算法独有参数平铺在 `[algorithm]` 段）：

```toml
[algorithm]
solver = "nsga2"          # 七选一
population = 40           # 0 = 自动（nsga3/moead 取权重向量数）
generations = 60
crossover_prob = 0.9
mutation_prob = 0.25
```

### 4.3 跨算法可比性设计（关键工程决策）

1. **统一编码与评价**：个体 = `[]int`（运单→车辆），评价统一走 `evaluateState`（4 目标向量 + ε 分数），M/C1/A3 同口径；
2. **ε-约束支配**（种群算法选择压力）：硬可行 > 不可行 → 软约束违反量低者优 → 4 主目标帕累托支配——进化压力指向"**可满足软约束的前沿**"，与主要目标法语义一致（Deb 约束支配的主要目标法形态）；
3. **ε-终选统一**：各算法最终候选集（终代第一前沿/档案）交派发器按 ε 分数统一裁决，**不各自为政**；
4. **随机源统一**：全部走实验种子 RNG，单线程确定性——**同种子逐 tick 复现对七种算法一致成立**；
5. **收敛曲线统一**：SA = 温度步进、种群算法 = 代数步进（`ConvergencePoint.Temp` 承载），同一结果页图表渲染；
6. **模式兼容**：weighted 旧标量化模式仅 sa/nf 支持（种群算法依赖目标向量），派发器自动回落 SA 并记日志；旧参数 `mode="nf"` 映射 NF 求解器。

## 五、实验验证（真实运行数据）

### 5.1 实验环境

演示沙箱 #1（20 辆川A车队，1146 个成都真实 POI），种子 12345，2 虚拟小时（加速比 200），日均 60 单（稀疏场景，约 5 单实际到达），主要目标法模式。

### 5.2 验证一：主目标切换改变调度行为（C2 ↔ U2，同种子）

| 实验 | 求解器 | 主目标 | C2 单位成本 | U4 空驶率 | T2 P95 | 总成本 |
|---|---|---|---|---|---|---|
| #17 | SA | **C2** | **0.59** | **0.48** | 0 s | **44 453** |
| #18 | SA | **U2** | 0.64 | 0.62 | 8 s | 48 643 |

**结论**：仅切换 `[objectives].primary`（其余参数与种子完全一致），调度行为即发生显著迁移——C2 主目标下单位成本/空驶率/总成本全面更优；U2 主目标为追求装载率**主动牺牲**约 9.4% 总成本与 14 个百分点空驶率。**权衡方向与指标体系文档 §2.1 预言的矛盾关系完全一致**——主要目标法的"选择与更换"机制真实生效。

### 5.3 验证二：求解器插件对比（primary=C2，同种子）

| 实验 | 求解器 | C2 | U4 | 总成本 | 求解耗时/批 | M1 精确率 | 前沿均值 |
|---|---|---|---|---|---|---|---|
| #17 | sa | **0.59** | **0.48** | **44 453** | 3.4 ms | 80% | 1.0 |
| #19 | nsga2 | 0.63 | 0.59 | 48 157 | 11.1 ms | 80% | 0.8 |
| #20 | spea2 | 0.63 | 0.59 | 48 012 | 25.1 ms | 80% | 0.8 |

**结论**：

- 三种求解器均完整跑通全流程（数据生成 → 仿真 → 终态结果落盘），收敛曲线 200 点带**代数步进**与前沿规模（种群算法）；
- 本稀疏批次场景（单批 1~3 单）下 SA 综合表现最优（其迭代预算 ~4000 次评估 vs 种群算法 2400 次）；种群算法在小批次上探索空间有限，属**符合预期的算法特性**——平台的意义正在于让这类对比可被便捷地实验出来；
- M1 精确率同为 80%：算法层指标在**同一目标口径**下评估，跨算法可比；
- A3 优化 gap = 0%：小规模批次上 SA/NSGA-II 均达到精确枚举的最优解。

### 5.4 验证三：单测与工程指标

- `go test ./internal/task/` 全绿：含**注册表、7 求解器完整求解、同种子确定性（两次运行指派一致）、NSGA-II 主目标切换、weighted 回落、非支配排序/拥挤度/Das-Dennis 点数（H=4,M=4 → 35）/MOEA-D 三种聚合/SPEA2 适应度/MOPSO 档案更新**等 15+ 新用例；
- `go vet` / `go build` / `npm run build` 全部通过；
- 冒烟实验可复现：同种子重跑结果一致（确定性保证）。

## 六、工程亮点小结

1. **科学性**：主要目标法 + 帕累托档案的求解语义与理论口径严格对应；M/C1/A3 算法层指标随目标切换联动；批次投影口径与全局指标同源；
2. **可复现**：七种求解器全部走种子 RNG 单线程确定性——算法对比实验天然可信；
3. **可扩展**：新增求解器 = 实现一个接口 + init 注册（约 100~250 行/算法），零侵入调度链路；
4. **可配置**：算法选择与独有超参全部进实验参数 TOML，与沙箱"参数快照 + 种子"实验范式一体；
5. **可观测**：主目标/软约束满足率/帕累托前沿从求解内核贯穿到实时看板、终态结果、报告导出（HTML/MD/JSON）；
6. **兼容性**：旧实验参数（weights/soft_constraints/mode=nf）自动迁移映射，旧数据不受影响。

### 7.4 预期答辩问题与要点回答

| 可能提问 | 回答要点 |
|---|---|
| 为什么用主要目标法而不是加权和？ | 加权和权重敏感、单点解无权衡信息；主要目标法语义明确（主目标唯一硬性）+ 帕累托档案保留权衡解，ε-终选"可行优先"近似字典序 |
| 各算法结果可比吗？ | 统一编码/评价/终选/随机源/收敛记录五统一；M/C1/A3 与调度器同目标口径（§4.3） |
| 结果可复现吗？ | 种子 RNG + 单线程 tick + 虚拟时钟；单测含同种子两次运行一致用例 |
| 种群算法为何本场景不如 SA？ | 稀疏批次（1~3 单/批）搜索空间小 + 评估预算差异（2440 vs 4000 次）；换更大批次/更高订单密度结论可能反转——这正是平台要支持的研究问题 |
| 软约束满足率 0% 说明什么？ | 稀疏场景下 F1 基尼结构性偏高（5 单/20 车，任意指派 gini≈0.9 > 0.4 预算）——软约束如实报告不可满足而非硬失败，恰好体现"软性限制"语义 |
